# Design Decisions & UI/UX Principles
**Project**: The Lenny Growth Assistant

## 1. UI/UX Principles

- **Focus Over Flash**: The primary interaction is reading deeply technical product/growth content. As such, the UI employs a stark, minimalist monochrome aesthetic (high contrast blacks, whites, and subtle grays) to eliminate distraction. We intentionally avoided neon/gradient trends to communicate "enterprise reliability" rather than "experimental AI."
- **Content is King**: The chat panel and artifact viewer take up the maximum possible screen real estate. The sidebar history is collapsible to reduce visual clutter during deep work sessions.
- **Native Rendering**: AI artifacts (like HTML tools) should not feel like raw text. The application uses a split-pane "Artifact Viewer" to render interactive HTML and structured Markdown securely alongside the conversation.

## 2. Information Architecture (IA)

1. **Authentication Layer**: A simple, centralized login page that gates access and establishes user context for session ownership.
2. **Global Navigation (Sidebar)**: A collapsible drawer on the left side that lists historical chat sessions, ordered by recency.
3. **Main Content Area (Center)**: The primary conversational interface.
4. **Contextual Panel (Right)**: The Artifact Viewer, which slides in dynamically only when an artifact (Markdown/HTML) is generated by the assistant.
5. **Settings (Modal)**: User preferences and API key configuration (Claude) accessible via the top-right navigation.

## 3. Key Interaction States

- **Dynamic Model Fallback**: If the user submits a prompt without a configured Claude API key, the UI seamlessly routes the request to the local Ollama instance, displaying a discrete "Ollama" badge in the header to maintain transparency.
- **Streaming Responses**: Token-by-token streaming is implemented to reduce perceived latency. The user sees a "typing indicator" immediately upon submission.
- **Citations Toggle**: Each message generated by the agent includes a hidden `details` accordion at the bottom containing the specific chunks of text retrieved from Lenny's transcripts. This builds trust without cluttering the main response.

## 4. Responsive Behavior

- **Mobile View (< 768px)**: 
  - The Artifact Viewer transforms from a side-by-side split pane into a full-screen modal to preserve legibility.
  - The Sidebar is hidden behind a hamburger menu and acts as a slide-over overlay rather than a pushed margin.
- **Desktop View (> 768px)**: 
  - Utilizes CSS Grid/Flexbox to comfortably position the Chat Panel and Artifact Viewer side-by-side. 
  - The sidebar pushes the main content, keeping layout shifts predictable.

## 5. Accessibility Considerations

- **Color Contrast**: The monochrome palette was specifically chosen to exceed WCAG AA standards (4.5:1 contrast ratio) for all text elements.
- **Semantic HTML**: Proper use of `<aside>`, `<header>`, `<ul>`, and `<button>` tags ensures screen readers can parse the document tree efficiently.
- **Keyboard Navigation**: All interactive elements (sidebar toggles, chat inputs, artifact buttons) have visible `:focus-visible` outlines and can be triggered via standard `Tab` and `Enter` keystrokes.
- **Flicker-Free Theming**: CSS variables dictate the light/dark mode, ensuring that users with light-sensitivity are not blinded by a flash of white text before React hydrates the DOM.
